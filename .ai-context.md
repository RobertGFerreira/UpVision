## 1. Descrição do Domínio e Missão

O **UpVision** é uma plataforma corporativa desktop especializada em **Visão Computacional**, **Super-Resolução (Super-Resolution - SR)** e **Inferência Visual em Borda (Edge/Local AI)**. 

O software foi concebido para resolver o trilema clássico de Visão Computacional:
* **Privacidade Absoluta (Zero-Data Leakage)**: O processamento de imagens e vídeos ocorre 100% on-premises / on-device, garantindo que nenhum frame ou metadado visual seja exposto a provedores externos de nuvem.
* **Latência Mínima e Alto Throughput**: Pipeline otimizado que prioriza aceleração por hardware via GPU dedicada NVIDIA (CUDA com precisão FP16/half) e fallback robusto para CPU.
* **Robustez Operacional**: Verificações de ambiente prévias (preflight checks), tolerância a falhas na inferência e gerenciamento dinâmico de pesos de modelos sem necessidade de intervenção manual no sistema de arquivos.

## 2. Arquitetura do Sistema e Stack Validada

O UpVision adota arquitetura modular desacoplada entre a camada de apresentação gráfica (GUI), o orquestrador de tarefas assíncronas e o motor de inferência profunda.

```text
UpVision/
├── main.py                 # Interface gráfica desktop (Tkinter/ttk), event loop e binds
├── engine.py               # Motor de inferência (Real-ESRGAN / PyTorch / OpenCV)
├── model_manager.py        # Modal de download, inspeção e seleção dinâmica de modelos
├── preflight.py            # Verificação prévia de requisitos de runtime e dependências
├── logging_config.py       # Configuração de logging estruturado (console + arquivo rotativo)
├── requirements.txt        # Dependências pinadas (Python 3.12 com suporte CUDA)
├── run.bat / run.sh        # Scripts de bootstrap automático do ambiente virtual
├── tools/                  # Utilitários de diagnóstico, download e correção de runtime
│   ├── download_models.py  # Download seguro de pesos com validação de tamanho/integridade
│   ├── env_check.py        # Relatório de diagnóstico de hardware, CUDA e pacotes
│   └── patch_basicsr_...py # Patch de compatibilidade torchvision/basicsr
├── assets/                 # Recursos gráficos canônicos e imagens de teste
├── logs/                   # Logs rotativos da aplicação (upvision.log)
├── models_realesrgan/      # Armazenamento local de checkpoints neurais (.pth)
└── specs/                  # Especificações técnicas, planos e checklists de execução
```

### Stack Tecnológica
* **Linguagem**: Python 3.12 (versão padrão homologada para compatibilidade com o ecossistema `basicsr` / `realesrgan`).
* **Framework Deep Learning**: PyTorch 2.x com suporte a CUDA 12.1+ / cuDNN (fallback automático para CPU).
* **Super-Resolução**: Real-ESRGAN (arquiteturas `RRDBNet` x2plus e x4plus com 23 blocos residuais).
* **Processamento de Imagem**: OpenCV (`opencv-python-headless`), Pillow (`PIL`) e NumPy.
* **Interface Gráfica**: Python standard `tkinter` com temas `ttk`, renderização multithreaded para não bloquear a UI durante inferências pesadas.
* **Concorrência**: Threads dedicadas com controle cooperativo via `threading.Event` (`stop_event`) e filas thread-safe (`queue.Queue`).
* **Logging**: `logging.handlers.RotatingFileHandler` com rotação a 5 MB e retenção de 3 backups.

## 3. Fluxos de Execução Críticos

### A. Inicialização e Preflight Check
1. `logging_config.setup_logging()` é chamado imediatamente ao iniciar o processo.
2. `preflight.check_dependencies()` valida a integridade de módulos críticos (`torch`, `cv2`, `PIL`, `numpy`, `basicsr`, `realesrgan`).
3. Detecção de hardware via `torch.cuda`: verifica disponibilidade de GPU, nome da placa, contagem de dispositivos e memória VRAM livre.
4. Se dependências essenciais estiverem ausentes, uma interface de diálogo exibe diagnóstico amigável antes de encerrar limpo.

### B. Inicialização de Modelos
1. A pasta `models_realesrgan/` é inspecionada.
2. Caso nenhum modelo `.pth` seja encontrado, o `ModelManagerDialog` modal é aberto automaticamente, permitindo ao usuário baixar os pesos oficiais via streaming com barra de progresso.
3. Modelos suportados no registro padrão:
   - `RealESRGAN_x2plus.pth` (escala 2x, ~64 MB)
   - `RealESRGAN_x4plus.pth` (escala 4x, ~64 MB)

### C. Pipeline de Inferência e Comparação Visual
1. Imagens são carregadas via diálogo de arquivo ou lote.
2. O processamento é submetido em thread separada com `stop_event` ativo.
3. Eventos de progresso (`"progress"`, `"done"`, `"error"`, `"cancelled"`) são consumidos na UI pela rotina de polling periódica.
4. O visualizador de comparação permite inspeção lado a lado com split dinâmico entre a imagem original e o resultado upscalado.

## 4. Diretrizes de Governança para Agentes de IA

1. **Idioma de Trabalho**: Toda comunicação, docstrings, comentários de código e mensagens de commit devem ser redigidos em **Português Técnico (PT-BR)**.
2. **Propriedade Intelectual**: Jamais referenciar repositórios públicos, licenças permissivas externas para o código corporativo ou práticas de código aberto.
3. **Estabilidade de Dependências**: Python 3.12 é a versão canônica. Não atualizar bibliotecas que quebrem a compatibilidade do `basicsr` sem prévia validação técnica.
4. **Proteção de Segredos e Dados**: Manter `.gitignore` rigorosamente atualizado, impedindo o versionamento de pesos binários pesados, arquivos de log locais e credenciais.
